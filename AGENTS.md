# AGENTS.md — guide for AI agents contributing to ai-doc2md

This file is for AI coding agents that read, test, or change this project. The human-facing rules are in [CONTRIBUTING.md](CONTRIBUTING.md).

## What this project is

`ai-doc2md` converts documents to Markdown. It picks an engine by file extension: pandoc for text-based formats, Docling for PDFs, slides, spreadsheets, and images. Everything runs locally.

## Promises to keep

1. **Local only.** Do not add calls to cloud APIs, telemetry, or uploads of document content.
2. **Visible filtering.** Anything the Docling header/footer filter removes must be reported in the output note and on stdout. Never remove content silently.
3. **Explicit routing.** A format must appear in `formats.py` to be accepted. Unknown types exit with code 2. Never guess an engine for an unknown format.
4. **Forced engines fail loudly.** `--engine pandoc` on a PDF is an error, not a fallback.
5. **Optional heavy dependency.** Docling is an optional extra. Import it only inside `docling_engine.py`, so pandoc-only use never loads PyTorch.
6. **Stable CLI.** Keep the `convert` subcommand, its flags, and the exit codes (0 success, 1 failure, 2 unsupported type) backward compatible.
7. **Relative image links.** Image links in the output must resolve relative to the Markdown file.

## Layout

```
src/ai_doc2md/
  cli.py             argument parsing, dispatch, exit codes
  formats.py         extension -> engine table (the single place to add a format)
  pandoc_engine.py   pandoc conversion, image extraction, link clean-up
  docling_engine.py  Docling conversion, header/footer filter, optional dependency
  furniture.py       detection and removal of repeated running headers and footers
  postprocess.py     clean-up of pandoc output
tests/
  test_formats.py         routing table
  test_postprocess.py     link clean-up
  test_pandoc_engine.py   real pandoc runs on small generated files (skipped without pandoc)
  test_cli_routing.py     CLI dispatch with the engines mocked
  test_furniture.py       Docling filter on synthetic documents (needs the docling extra)
SKILL.md             usage guide for agents that call the tool
```

## Setup and checks

Keep the virtualenv outside any folder synced by a file-sync tool.

```bash
sudo apt install pandoc
python3 -m venv ~/.venvs/ai-doc2md-dev
~/.venvs/ai-doc2md-dev/bin/pip install -e ".[docling,dev]"
~/.venvs/ai-doc2md-dev/bin/python -m pytest -q
```

Tests must not download models or call the network. Test documents must be generated by the test itself or be synthetic. Never commit a real document or its converted output.

## Adding a format

1. Add the extension to `PANDOC_EXTENSIONS` (if pandoc reads it well) or `DOCLING_ONLY_EXTENSIONS`.
2. Add a routing case to `tests/test_formats.py`.
3. If pandoc is used, check that pandoc's own input list includes the format (`pandoc --list-input-formats`).
4. Describe the format in `README.md` and `SKILL.md`.

## Rules for changes

- **Keep changes small.** One fix or feature per pull request.
- **Add a test for each behaviour change**, including the failure case.
- **Do not change the Docling filter's default behaviour** without an issue and a discussion. It changes every user's output.
- **Keep the Python floor at 3.10.**
- **Do not add a new required dependency.** New optional extras need a note in the README explaining size and purpose.

## Pull request description

Include:

- What changed and why, in two or three sentences.
- The test command and its result.
- For routing or engine changes: the formats you checked and how.
- A line stating that the change was produced with AI assistance, and which tool and model you used.

## Security

Do not report vulnerabilities in a public issue. Use a private security advisory on GitHub.
